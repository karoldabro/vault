`recycling-api` registry file; PMD CPD (see Open & deferred); a `phparkitect.php` rules file for
`recycling-api` itself (the framework row only fires when a project already has one — none is added
here, so `laravel-arkitect` correctly reports `absent`/not-applicable on `recycling-api` today).

`git rm` or `docker compose build server` (built once for SC-2) leaves no state to unwind — Docker
build cache is disk space only, not a running service.

## Test design dossier
Decision table — row applicability by `(stack, stack_packs key present, stack listed)`:

| stack | key absent | key present, listed | key present, not listed |
|-------|-----------|----------------------|--------------------------|
| `any`/`harness` | runs (`detect` only) | runs (`detect` only) | runs (`detect` only) |
| `laravel`/`nuxt`/`flutter`/`python`/`sql` | runs (`detect` only) | runs (`detect` still applies) | skipped, no `ran:`/`absent:` line |

Fault hypothesis: a malformed `stack_packs` value (trailing comma, empty string after the colon) must
be treated as absent, not as "zero stacks" — an empty declared list would silently skip every
named-stack row on a repo that meant to opt in, which is a worse failure than never gating at all.
T-40 covers the empty-after-colon case.

Second fault hypothesis: a parser tested only against a hand-authored guess at a tool's format can
pass while matching zero real findings. T-41, T-42 and T-45 run each parser against the real fixtures
in `tests/fixtures/probe/`, captured from an actual run of each tool (§Verified current state).
