# probe-kit-core — plan

## Task
Session S4 of `vault/plans/2026-09-21-0900-architecture-first-planning.md`. Build the probe kit core. It is `bin/probe.sh` with `list`, `detect`, `run <stage>`, `diff` and `scale`, and `probes/registry.tsv`. It ships harness probes run on this repo, three schema probes (duplicate columns, foreign-key indexes, naming), a similar-symbol probe and the verified tool list. Keywords: probe, registry, finding row, absent tool, executes-repo-code, scale, harness, sql schema.

## Open & deferred
- deferred: rows for tools whose output this session cannot capture on this machine (PHPArkitect, PMD CPD, tbls, DCM, Qlty, Semgrep). Session S9 adds each with a captured fixture.
- deferred: complexity gating and Laravel migration probes. A PHP migration is not SQL, so S9 feeds `php artisan migrate --pretend` output into the SQL probes.
- deferred: Dart symbols in the similar-symbol probe; a regex for Dart method names produces mostly false matches.
- deferred: SQL that drops or renames a column across migrations. The SQL probes read CREATE TABLE, CREATE INDEX and ALTER TABLE ADD only, so a schema built from many migrations can report `column-drift` for a column that was later dropped.
- deferred: one shared markdown table reader. `bin/gate.sh`, the renderer and the similar-symbol probe each read tables; extract `lib/md-table.sh` when a fourth reader appears.
- deferred: `bin/release-check.sh` and `bin/doc-lint.sh` each list changed and untracked files; point them at `lib/probe-scope.sh` in a later session.
- deferred: a scrubbed environment (`env -i` with an allowlist) for every cell, and a memory limit. Cells run with a CPU limit of twice the timeout, an output limit and a process-group kill, and no memory limit.
- accepted limit: `similar-symbols` and the SQL probes are text scans. A symbol built by a macro, or SQL written by a tool at run time, is invisible to them. A SQL column named `key` or `period`, `CREATE TABLE ... AS SELECT`, and a backslash-escaped quote in a string are not read correctly.
- accepted limit: the kit runs a repo's own tool directories (`.venv-probes/bin`, `node_modules/.bin`) for a `yes` row unless the caller passes `--no-repo-code`. With `--allow-repo-registry` it prints a repo row's install text, with control bytes removed and at most 300 bytes. Session S7 decides who passes the flags.
- accepted limit: `md-links` costs about 20 ms per markdown file, so it is rated `M`, and 6000 files reach the 120 second timeout. `dead-files` counts a file-name stem as a mention, so common words hide unused files. Bytes 0x80 to 0x9f pass the control-byte filter, because stripping them would damage UTF-8 text.
- accepted limit: the cost thresholds behind `scale` (2000 and 10000 tracked files) are unmeasured defaults. Session S5 measures them (D-10 of the master plan).
- accepted limit: `parse_claude_validate` and `parse_typos_json` need `jq`; a machine without it gets `absent: jq`.
- known noise: `claude plugin validate` warns that every command step file lacks frontmatter, so this repo yields about 44 warnings from that one probe. `bin/probe.sh run plan` on this repo exits 1 with findings.

## Decisions

| decision | reason | record |
|----------|--------|--------|
| D-1 A registry row is `id stack stage detect run parser cost executes-repo-code install` in this order (the order of contract C-3), tab separated. `parser` is `native` or the name of a function in `lib/probe-parsers.sh`. The pair `id`+`stage` is unique | C-3 fixes the columns; a name in `parser` says how output becomes rows | local |
| D-2 `plan` rows run on the whole tree under `run plan` and on changed files under `diff`. `diff` rows run only under `diff`. `review` rows run under `run review` and under `diff`. `run` rejects the stage `diff`. `diff` runs every row of the three stages and keeps the findings whose file changed | one script needs one row, and C-3 names three stages without saying when each runs | local |
| D-3 A finding is `probe file line severity rule message`. `lib/probe-emit.sh` is the only place that builds one, and the core rewrites field 1 to the registry id, strips control bytes from fields 2 to 6, caps the message, and refuses an absolute or `..` file. The core buffers a probe's rows and prints none of them when that probe failed | six writers of a row drift, and a file name or message can carry a second row | local |
| D-4 Exit 2 when any applicable probe is absent, failed, timed out, over its output cap or printed a malformed row. Else exit 1 when any finding exists. Else exit 0. Findings go to stdout and status lines to stderr. Every probe that ran prints `ran: <id>: <n>` | a missing tool must never read as a clean run, and a clean run must be told from a probe that never loaded | vault/decisions/ADR-003-tool-grounded-findings.md |
| D-5 No code path runs an `install` cell. An absent tool prints `absent: <id>: <install>` with control bytes removed | consent for package changes belongs to the operator | local |
| D-6 A repo's own registry is read only under `--allow-repo-registry`. Its rows count as `executes-repo-code: yes` whatever the cell says. A repeated `id`+`stage` across origins exits 2. `--no-repo-code` skips every `yes` row and every repo row. A repo registry identical to the framework registry loads once as framework origin. `list` runs no cell. `detect` runs a repo-origin `detect` cell only under `--allow-repo-registry` and never under `--no-repo-code` | a pull request under review can add a row, and the default must refuse | vault/decisions/ADR-009-v-cr-sandboxed-execution.md |
| D-7 `scale` prints `files`, `lines` and `max-cost` (`L` up to `PROBE_SCALE_L` tracked files, `M` up to `PROBE_SCALE_M`, `S` beyond); `run --max-cost` skips costlier rows | D-10 of the master plan bounds cost, and the thresholds are unmeasured defaults | local |
| D-8 A native probe is a bash script that prints rows through `probe_finding`, uses POSIX `awk` under `LC_ALL=C`, and reads only the files that `probe_files` lists. `probe_files` prints NUL-separated regular files with no symlink in the path, skips any name holding a control byte, and says how many it skipped on stderr | the container runs BusyBox `awk`, and awk and grep follow a symlink to a host file | local |
| D-9 A registry row exists only for a tool whose flag the verification file marks verified or partly verified and whose real output a parser test consumes | an unverified flag or an untested parser produces false grounding | vault/decisions/ADR-003-tool-grounded-findings.md |
| D-10 A `detect` or `run` cell runs with `bash -c`, working directory the target repo, and the exported variables `PROBE_REPO`, `PROBE_FRAMEWORK`, `PROBE_FILES` (the path of a NUL-separated list file that the core writes to a temp directory outside the repo) and `PROBE_SPEC`. A probe reads that list with `read -r -d ''` and gives awk one file at a time. A cell reads them as `"$PROBE_REPO"`; the core never substitutes text into a cell. A native probe row is `"$PROBE_FRAMEWORK/probes/harness.sh" --check md-links`. A cell prints a variable only as `printf '%s' "$VAR"` | text substituted into a shell string runs a path such as `r$(touch x)` | local |
| D-11 Every child process runs as a `set -m` job that a core-owned watchdog stops after `PROBE_TIMEOUT` seconds with TERM, then KILL to its process group after 2 seconds. The core kills what is left of the group after every run, and a signal to `bin/probe.sh` stops the running group. Its stdout goes to a private temp file under `ulimit -f` for `PROBE_OUT_MAX` bytes, and the core reads the job's exit code apart from that file. Every git call uses `-c core.fsmonitor=false -c core.hooksPath=/dev/null`, `GIT_CONFIG_GLOBAL=/dev/null` and `GIT_CONFIG_NOSYSTEM=1`; `probe_changed` uses only `diff --name-only -z --relative` and `ls-files -z -o`, and returns 2 when git fails. Git also runs with `GIT_NO_LAZY_FETCH=1`, and every `filter.<name>.clean`, `smudge` and `process` of the repo's config is overridden. `bin/probe.sh` keeps only absolute `PATH` entries and unsets `BASH_ENV` and the `GIT_DIR` family. The core resolves `git`, `awk`, `jq` and `timeout` to absolute paths at start and appends repo tool directories to `PATH` only for `yes` rows. `--only` matches `^[a-z0-9-]+$` and `--base` passes `rev-parse --verify --end-of-options` | a repo's git config, `PATH` and process tree run code of the person who reads the repo, and BusyBox `timeout` kills only the direct child | vault/decisions/ADR-009-v-cr-sandboxed-execution.md |
| D-12 A tool row's own exit code is ignored while its parser exits 0, except 124, 126, 127 and above 127, which mean failed. A native row fails on exit 2 or above | lizard exits 1 and typos exits 2 on findings | local |
| D-13 The similar-symbol probe matches a planned need to a symbol when they share one non-stop token or a prefix of four characters. The stop tokens are `get set is has a an the of to and for new` | the overlap rule decides SC-6, and a stated rule is testable | local |
| D-14 A row's tool is the first word of its `run` cell. A word that starts with `"$PROBE_FRAMEWORK/` is present when that file is executable. Any other word is present when `command -v -- <word>` finds it. The core never runs `eval` on a cell. `probe_tool_present` in `lib/probe-registry.sh` does this for `list`, `detect` and `run` | native rows would otherwise read as absent, and `eval` would run repo text in `list` | local |
| D-15 A `plan` row's `detect` cell is `true` when the repo holds any file the probe reads: a `.md` file for `md-links`, `dead-files` and `token-size`, a `.sql` file for the three SQL rows, a source file for `similar-symbols` | SC-4 and SC-8 need the harness rows to load in a repo with one markdown file | local |

## Test plan
Bats cases in `tests/unit/probe.bats`, run in the container with `./tests/run.sh tests/unit/probe.bats`. Each case builds a fixture repo in a temp directory, runs `bin/probe.sh`, and asserts stdout rows, stderr status lines and the exit code. Failure modes covered:
- a registry line with eight fields, an unknown stage, a duplicate row, or a row id repeated across origins;
- a probe printing a five-field row, exiting 2, running past the timeout, or printing without end;
- an absent tool whose install command would create a file;
- a symlink to a host file, a symlinked directory, and a file name holding a tab, a newline, a quote or `$()`;
- a message or file name that carries a second finding row;
- a repo with `core.fsmonitor` set, a repo registry claiming `no`, and a non-git repo in `diff`;
- a `--base` value starting with a dash, and CRLF SQL.
