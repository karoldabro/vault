quality-loops — plan

Task

Split EXECUTE in /v-work and /v-team into three loops with separate owners. The execution loop writes production code and runs the repo's static checks on the diff before it calls a unit done. The code-review loop critiques design the way a senior developer would and drops anything a static tool already reports. The testing loop writes tests, measures changed-line coverage against an 80% floor and runs mutation testing on the diff, and independent reviewers label every surviving mutant. Quality tools come from a new plugin extension point check, so the vault-quality-gates plugin can supply them; a repo without it falls back to its lint_command and test_command.

Needs your decision

  • needs the operator: when this plan closes, no repo enforces the 80% floor or runs mutation testing. Both arrive with the deferred vault-quality-gates session below. Until then every testing loop prints coverage unmeasured: <reason>, and the operator's 80% criterion stays unmet.

Interfaces

  • bin/vault-check.sh.static(repo: path, base: ref): exit 0, 1 or 2 with check lines
  • bin/vault-check.sh.tests(repo: path, base: ref): exit 0, 1 or 2 with check lines
  • lib/plugin-registry.sh.vault_plugin_run_check(stage: string, repo: path, base: ref): highest point exit, clamped to 2
  • lib/plugin-registry.sh.vault_plugin_check_declared(repo: path): 0 when an opted-in plugin declares check, else 1
  • lib/plugin-registry.sh.vault_plugin_opted_in(vault_md: path): plugin names one per line; 2 on two plugins lines
  • lib/vault-md.sh.vault_md_key(repo: path, key: string): the value, or 1 when the file or key is absent
  • extend/check.sh.static(repo: path, base: ref): exit 0, 1 or 2 with check lines
  • extend/check.sh.tests(repo: path, base: ref): exit 0, 1 or 2 with check lines
