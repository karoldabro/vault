Architecture-first planning

Every /v-team and /v-pm plan will carry a checked architecture spec and a picture-first summary like this page, so you judge the design before any code exists.

What you are asked to approve

  • This session builds S1 and S2 only: the research write-up and the architecture-spec contract with its gate (26 files, all additive, 22 planned test cases).
  • S3 to S9 are later sessions, each with its own plan: human artifact renderer, probe kit, plan-time auditors, master plans, probe results in every review panel, an on-demand comment-to-rule skill, per-stack probe packs.
  • No tool is installed anywhere. A missing probe reports the project-scope install command and waits for you.

Your review comments become rules, on demand (S8)

What you check yourself, and what machines check

You, on the plan page

  • Does this solve the right problem, and is anything in scope that should not be?
  • Does the data model fit the domain: tables, keys, ownership of each field?
  • Does each piece of logic sit in the right layer?
  • Is each new abstraction earned, and does the reuse map name what already exists?
  • Which paths touch security or money?

Probes, before you see the plan

  • Spec completeness, typed parameters, keys and indexes (S2)
  • Duplicate columns, duplicate methods, naming (S4, S5)
  • Complexity, layering rules, dead code (S4, S8)
  • Passing tests do not prove coherence: in one study 97.0% of structural failures evaded type checking and 100% evaded tests and static security scans

Open points and unverified claims

  • Longer planning reducing rework has no controlled study behind it. The plan targets reuse, layering and data model, where agents fail most, and caps the added cost at 50% of PROPOSE.
  • Twelve probe-tool claims (licences, JSON flags, Dart and Vue support) are unverified. S4 checks each before a probe is registered.
  • Most research figures came through a summarising tool. S1 re-opens each source before quoting it.
  • Publishing an Artifact from a subagent is untested. S3 tests it and falls back to a local HTML file.
  • Two decision records already share the number ADR-030. This is an existing defect, not caused by this plan.
