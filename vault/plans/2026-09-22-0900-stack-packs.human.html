  • Is anything loaded every time that could load only when needed?

Task

Add probe-registry stack packs for Laravel (PHPStan + PHPArkitect), Nuxt (vue-tsc), Flutter (dart analyze) and Python (ruff) — SQL packs already exist from S4 — and let a repo declare which stack packs apply in its own VAULT.md, detected once at onboarding and hand-editable after, instead of every run re-guessing from scratch. Validate against /home/kdabrow/workspace/recycling-api (Laravel, real, via that repo's own Docker image) and /home/kdabrow/workspace/nuxt/woonuxt (Nuxt, real). Keywords: stack pack, probe registry, VAULT.md, onboarding detection, phpstan, phparkitect, ruff, dart analyze, vue-tsc.

Open & deferred

  • needs the operator: approve the five analyzer choices (§Decisions), the stack_packs VAULT.md key design, and the one new file in recycling-api (§Work items W-16) before EXECUTE.
  • deferred, not this plan's: sql-dup-columns/sql-fk-index/sql-naming only read .sql files. recycling-api's migrations are Laravel PHP (database/migrations/*.php), so the existing SQL probes correctly find nothing there — not a bug this plan introduces, and parsing PHP migration calls is a separate, larger probe this plan does not build.
  • deferred, not this plan's: lib/arch-check.sh's vault_key helper is not extracted to a shared lib; bin/probe.sh gets its own three-line copy — see the Reuse map for why.
  • deferred, not this plan's: vault/research/probe-tool-verification.md names PMD CPD as a pending addition for session S9. PMD CPD is cross-language duplicate detection, not a stack-specific analyzer, and stays out of this plan's scope; its entry now records that explicitly.
  • unverified: vue-tsc is not installed in woonuxt, so SC-6 exercises the detect-and-absent: path, not a real findings run. Installing it there would mutate a repo outside this plan's declared scope, so this plan does not do it.
  • every tool CLI flag and output format in §Decisions was confirmed by an actual run, not by documentation alone — see vault/research/probe-tool-verification.md.

Decisions

decisionreason
Laravel gets two probes: vendor/bin/phpstan analyse --error-format=json --no-progress, parsed by a new parse_phpstan_json, and vendor/bin/phparkitect check --format=json, parsed by a new parse_phparkitect_jsonvault/research/probe-tool-verification.md already committed session S9 to PHPArkitect (architecture-rule checking); PHPStan adds general bug-finding that needs no project-specific rule config, closing the gap PHPArkitect alone leaves on a repo with no phparkitect.php
parse_phpstan_json reads files.<path>.messages[].{line,message,identifier} — there is no severity field, only ignorable; every message maps to severity errorverified by a real run inside recycling-api's server image (2026-09-22)
parse_phparkitect_json derives a finding's file from the fully-qualified class name under Laravel's own App\ → app/ PSR-4 convention, since PHPArkitect's JSON has no file field at all and this row is Laravel-onlyverified by a real run in a scratch project (2026-09-22): {"totalViolations": N, "details": {"<FQCN>": [{"error", "line"}]}}, keyed by class, not path
Python probe runs ruff check --output-format json, parsed by a new parse_ruff_jsonverified by a real run in a scratch venv (2026-09-22): a JSON array of {"filename", "location": {"row", "column"}, "code", "message", "severity"}
Flutter probe runs dart analyze --format=machine, parsed by a new parse_dart_machine — never flutter analyze --format=machine, which does not existflutter analyze (Flutter 3.44.4) refused --format outright (Could not find an option named "--format", exit 64) when run for real; dart analyze --format=machine, the bundled Dart SDK's own command, produced real pipe-delimited output (SEVERITY|TYPE|CODE|PATH|LINE|COL|LEN|MESSAGE)
Nuxt probe runs vue-tsc --noEmit, parsed by a new parse_tsc_text matching path(line,col): error|warning TSxxxx: messageverified by a real, piped (non-TTY) run in a scratch project (2026-09-22): TypeScript's parenthesized non-pretty form — pretty mode with the colon-dash form is TTY-only, and bin/probe.sh always pipes a tool's stdout
recycling-api gets one new file, probes/registry.tsv, with a repo-scoped laravel-phpstan-docker row scoped to app/Http/Controllers whose run cell is docker compose run --rm --no-deps server vendor/bin/phpstan analyse --error-format=json --no-progress app/Http/Controllers 2>/dev/null | sed 's#/app/##g', reusing the framework's parse_phpstan_jsonoperator's stated choice ("use docker in the recycling_api repo") over picking a different delivery target; a whole-project scan (.) took over 10 minutes and still errored out — app/Http/Controllers alone runs in under two; the sed needs g because PHPStan's JSON is one line, so every /app/ past the first must still be stripped; the shipped framework row stays plain (vendor/bin/phpstan on host) because most Laravel repos don't need Docker to match their own PHP version — this is recycling-api's own environment quirk, expressed the way the registry contract already supports per-repo overrides
SC-2's check script runs with PROBE_TIMEOUT=180, not the registry default of 120a real PHPStan pass over app/Http/Controllers, inside a freshly started container, measured at 1m47s; the override lives in the check script, not the registry row, since most Laravel repos are smaller or run on bare host with no container start-up cost
A repo's VAULT.md gets a new ## probes section with a stack_packs: <comma-separated ids> key, written by bin/vault-init.sh and hand-editable, applied to every named-stack row (laravel, nuxt, flutter, python, sql — not any/harness)operator's stated requirement: some repos install only a subset of analyzers, or a detected stack doesn't apply there; recording the decision once at onboarding beats re-guessing every run, and matches the existing dod_profile onboarding pattern
Absent stack_packs key falls back to the pre-existing per-row detect cell aloneevery repo onboarded before this key existed must keep working unchanged
