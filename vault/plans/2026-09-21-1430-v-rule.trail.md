# v-rule — process record

Record class, so chronology belongs here and nowhere else. Its contract document is
`plans/2026-09-21-1430-v-rule.md`, which carries the current truth only.

## Decisions & trade-offs

| decision | alternative rejected | why it lost |
|---|---|---|
| Rule file is a declarative `.grep` data file run by a framework runner | a `.sh` rule script that builds rows with `probe_finding` | a comment is untrusted and the model drafts the rule, so a script would let a comment reach a shell |
| The registry row is generated from a template | the model writes the row | a typed cell is arbitrary shell run by the kit under `--allow-repo-registry` |
| Block a rule at more than 20 findings | a percentage of files; no limit | one number needs no file-count denominator, and 20 is half of the panel's 40-row block |
| Sandbox rows leave through stdout and stderr | a writable output mount; `docker cp` from a named volume | a writable host directory is a channel the container controls |
| Sandbox tags follow the run and the base registry | tag by id from the container's own output | a container that ran repo code can print any id |
| Scope B becomes S10 | build both in S8 | S8 is 19 files and S10 would add 15, past the size at which a unit drops work |
| Two containers for repo rows: template rows and hand-written rows | one container for all repo rows | a hand-written row runs pull request code and could forge a template row |
| `/v-rule` supports GitHub only | Bitbucket through login match | `list_comments` returns no numeric id, and a login can be renamed |
