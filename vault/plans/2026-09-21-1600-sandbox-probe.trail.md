# sandbox-probe — process record

Record class, so chronology belongs here and nowhere else. Its contract document is
`plans/2026-09-21-1600-sandbox-probe.md`, which carries the current truth only.

## Decisions & trade-offs

| decision | alternative rejected | why it lost |
|---|---|---|
| Posture `sandbox` reads the rows of the run only | run the host `pr` posture as well and merge | a second run reads the pull request on the host for no extra rows, and its status lines would have to be reconciled with the container's |
| A stage that never started falls back to posture `pr` | print INCOMPLETE and pass no rows | the operator asked for more than the plain review, and getting less is worse than getting the plain review |
| One container per template row | one container for all template rows | a runaway or memory-hungry rule would cost every rule's rows; the container start costs about a second per rule |
| `/repo` is a copy without `.git` | mount the clone and hide `.git` with a tmpfs | an empty `.git` directory still makes `probe_files` return 2 |
| `/framework` copied with `cp -RL` from the running tree | `git archive HEAD` | HEAD is not the code under test, and a plugin install has no `.git` |
| Base rules mounted at `/repo/probes` | a separate `/rules` mount with `--rules-dir` | the template row names `probes/rules/<slug>.grep` relative to the repo, so no new option is needed |
| Image named in `VCR_SANDBOX_MAP`, built by the operator | a framework Dockerfile and a default image | the framework would pin tool versions nobody audited, and a default image runs a name nobody chose |
| The driver reads a fake `docker` through PATH in graders | a mocked function | the graders exercise the real argument list and the real mount directories |
