Run the probes that execute repo code, and the repo's own rule files, inside the /v-cr --sandbox container, and tag their rows for the review panel (contracts C-2, C-3, C-6, C-8). Decisions

<!-- Ids SP-n are local to this plan; VR-n names a decision of vault/plans/2026-09-21-1430-v-rule.md. -->

decisionreason
SP-1 The probe image is named by the key probe-image of the user or global VCR_SANDBOX_MAP, built by the operator, and never built or pulled by the framework (docker image inspect first, then --pull never). It needs bash 4.4 or later, awk, grep, sed, coreutils (timeout, od, sort, tr, cut, mktemp), findutils and jq, plus lizard and typos for their rows and claude for claude-validate. commands/v-cr/sandbox.md S8 carries a sample Dockerfile. A tool the image lacks prints absent: <id>: <install>, the run reads INCOMPLETE, and the operator line reads install: add the tool of <id> to the probe image. A review reads INCOMPLETE until the image holds the tools of every row whose detect matches. There is no default image, and no key means the stage does not start. cr_is_envelope_key lists the key, so a repo file or an indication cannot set itthe container has no network, so nothing can install a tool at run time and an absent tool has to show as absent. A framework-built image would pin tool versions the operator never audited. A default image would run a name nobody chose. the kit expands empty arrays under set -u, which bash 4.4 accepts
SP-2 No failure of the container path runs a repo-code probe on the host. The driver has no host-run path, and posture sandbox never calls bin/probe.sh. A container failure, a timeout and an oversize stream become failed: lines of that run (SP-10). A missing image, missing docker, missing probe-image key, missing merge base or an over-limit tree makes the driver print probe-sandbox: <reason> on stderr and exit 3 without starting a container. Step 3.1 then runs --posture pr --repo "$SANDBOX_DIR", the clone of step 2.6, which skips every yes row and reads files as text; with no clone it prints Probes: not run, no checkout. A driver that exits 0 with failed containers is an incomplete run and has no fallbacka fallback that runs a yes row on the host runs pull request code exactly when the sandbox failed, which an attacker can cause by exhausting memory. pr is the review the operator gets without --sandbox
SP-3 There are three kinds of container: the native run (--no-repo-code, no --only), one run per framework row whose executes-repo-code is yes (--only <id>), and one run per template row of the base (--only <id>, --allow-repo-registry). The host keeps a row only when its id is a row of that run: the ids of the framework rows with no for the native run, and the one --only id otherwise. It splits each stream by field 1, passes each id's rows through probe_check_rows, and on a nonzero return discards all rows of that id and writes failed: <id>: malformed row. Rows of any other id are dropped and the run writes failed: <run>: rows named an id that is not a row of this run: <n>, where <run> is framework for the native run and the id otherwise. The native run drops the kit lines skipped: <id>: runs repo code, because the per-row runs cover those rows. A rule run needs a ran: <id>: line, because its detect cell is always true, and without one the host writes failed: <id>: no ran line. The other runs need none, because a row whose detect is false prints nothingthe finding row has no origin, so the run and the id are the only facts the host holds. One container per tool row limits a hijacked tool to forging rows under its own id
SP-4 A base without probes/registry.tsv writes no-rules: the merge base has no probes/registry.tsv to rules.status, starts no rule container, and reads complete. A base row that is not the output of rule-check.sh row writes skipped: <id>: hand-written row does not run in the sandbox, whatever its stage. A base id that also names a framework probe writes skipped: <id>: the id also names a framework probe. A rule file that is not a regular blob (a link, or over 8192 bytes) writes skipped: <id>: the rule file is not a regular file. Rows past PROBE_SANDBOX_RULES_MAX write skipped for the rest. The driver writes a new one-row registry.tsv for each rule container, holding only the vetted template row, and never mounts the base filea hand-written row at another stage with a template row's id would run under --only, and one malformed row would fail every rule container. A row that exists and did not run is a gap the critics have to know about
SP-5 The operator sees three states. Ran: the terminal Probes: line reads Probes: sandbox ran and the forge comment has no probe line. Not started: Probes: sandbox not started, <reason> in both, and posture pr ran (SP-2). Incomplete: Probes: INCOMPLETE, <a> absent, <s> skipped, <f> failed (sandbox) in both, and the terminal adds the install: lines. The reason is the text after probe-sandbox: on the driver's stderrthe operator needs to tell "never ran" from "ran and lacks something", and the comment on the forge carries no install text
SP-6 /repo is one copy of the files probe_files lists, without .git, shared by every container of the run. The driver creates probes/ in it and mode-sets the roots to 755 and the files to a+rX, because Docker cannot create a mount point in a read-only mount and uid 65534 cannot read a 0700 directory. Each rule container mounts its one-row registry and rule file at /repo/probes. /in is a directory mount that holds changed.list, and every mount ends in :ro. The container command is /framework/bin/probe.sh diff --repo /repo --changed-list /in/changed.list, with --no-repo-code, --only <id> or --only <id> --allow-repo-registry as SP-3 says. VR-4 mounted the clone and /rules; a clone with .git makes probe_files return 2 in a container without git, and the template row names probes/rules/<slug>.grep relative to the repothe copy holds exactly the files a probe may read, and no option like --rules-dir is needed
SP-7 /framework is a copy of bin, lib and probes of the running framework tree made with cp -RL, not git archive HEAD. VR-4 named git archiveHEAD runs the committed code and not the code under test, and a plugin install has no .git
SP-8 --base is a full commit id of 40 or 64 hex digits. Step 2.6 records PROBE_BASE (moved from step 3.1) as the full id printed by git merge-base in the clone, after step S2 fetches the base branch with enough history for it. The driver checks that git cat-file -t reads commit, lists the base with git ls-tree -z -l, and reads each rule file by object id with git cat-file blob. It accepts a slug matching ^[a-z0-9][a-z0-9-]{0,39}$ and modes 100644 and 100755 up to 8192 bytes. A base commit missing from the clone makes the driver exit 3 with the merge base is not in the clonethe clone is shallow, so the base can be missing, and the clone holds attacker objects
SP-9 Posture sandbox tags every row [confirmed] and runs nothing on the host. A native row is a check of the framework on the pull request files. A tool row is a tool of the operator's image on those files, limited by SP-3 to its own id. A template row is a check written by the base, which the pull request cannot edit. registry-edited is not printed and nothing is demoted, because no row of the run comes from the pull request's registry. --paths and the row cap still apply. The reader of the four files is its own function in bin/probe-panel.shVR-5 sets these tags; the run is the only source of origin
SP-10 Each container starts as docker run --rm --init --name <sandbox-name>-<n> --label com.vault.v-cr.sandbox=<sandbox-name> --network none --read-only --cap-drop ALL --security-opt no-new-privileges --ipc none --log-driver none --pull never --user 65534:65534 --memory <m> --memory-swap <m> --cpus <c> --pids-limit <p> --tmpfs /tmp:rw,noexec,nosuid,nodev,size=64m, each flag and value as two words, then -e PROBE_TOOLS_FROM=image, -e PROBE_TIMEOUT=<n> and -e PROBE_OUT_MAX=<n>, the mounts, the image and the command. VCR_SANDBOX_MAP keys memory (default 1g), cpus (1) and pids (256) must be positive numbers with an optional unit and are clamped to 8g, 4 and 1024, and a value of 0 reads as the default. The host runs the docker client under timeout of PROBE_SANDBOX_TIMEOUT (180 seconds) and writes its two streams to files under ulimit -f, then cuts each at PROBE_OUT_MAX bytes before it scrubs. The status lines are failed: <run>: container exit <n>, failed: <run>: timed out after <s> seconds and failed: <run>: printed more than <PROBE_OUT_MAX> bytes. A container failure or timeout still exits 0. The host caps the copy at PROBE_SANDBOX_FILES_MAX (20000) files and PROBE_SANDBOX_BYTES_MAX (200000000) bytes, runs host git and the copy under timeout, copies with cp --parents --no-dereference --no-preserve=all from the NUL list, and stops starting containers after PROBE_SANDBOX_TOTAL (900) seconds, writing skipped: <id>: the time budget is spent for the rest. A path holding : or , is refused before it reaches -vulimit -f limits files and not pipes, and docker defines 0 as no limit
SP-11 The container lists files with find, so the tools' whole-tree scans skip vendor/ and node_modules/. A rule row scans a changed file under them, because the changed list goes through probe_filter_list onlythe alternative is git in the container, which SP-6 excludes
SP-12 lib/probe-run.sh is not edited: probe_path in lib/probe-registry.sh is the one place the repo tool directories join PATH. The work directory of the driver is $(cr_sandbox_root)/<sandbox-name>-probe.XXXXXX, a leaf of its own, so the clone at $(cr_sandbox_root)/<sandbox-name> is never removed by the driverone home for the rule, and the critics still read the clone after the driver exits
