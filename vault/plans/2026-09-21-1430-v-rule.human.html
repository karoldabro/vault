Data flow

flowchart LR
    A["operator"] -->|"pull request: url"| B["commands/v-rule.md"]
    B -->|"comments: json, operator id: number"| C["bin/rule-check.sh own-comments"]
    C -->|"own comments: json"| B
    B -->|"draft rule, bad fixture, good fixture: files"| D["bin/rule-check.sh accept"]
    D -->|"rule, fixture: path"| E["probes/rule-grep.sh"]
    E -->|"finding rows: tsv"| D
    D -->|"accepted line or refusal: text, exit code"| B
    B -->|"draft directory: path, approval: yes"| F["bin/rule-check.sh install"]
    F -->|"rule file, fixtures, registry row: files"| G["target repo probes"]
    B -->|"indication: markdown"| H["project vault indications"]

Interfaces

  • rule-check.sh.own-comments(operator_id: int): the comments of that user id as JSON, throws exit 2
  • rule-check.sh.accept(repo: path, slug: string, rule: path, bad: path, good: path): `accepted <slug>: <n> of <files> files at <sha>` or a refusal, exit 0 or 1, throws exit 2
  • rule-check.sh.install(repo: path, slug: string, draft: path, stack: string): written paths and the record line, exit 0 or 1, throws exit 2
  • rule-check.sh.verify(repo: path, slug: string, indication: path): one status line, exit 0 or 1, throws exit 2
  • rule-check.sh.row(slug: string, stack: string): the template registry row, throws exit 2
  • rule-grep.sh.run(check: string, rule: path, repo: path, fixture: path, count_files: bool): finding rows, exit 0 or 1, throws exit 2
