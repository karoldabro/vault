decisionreason
VR-1 /v-rule writes only these files, and only after the operator approves the drafted set. Repo: probes/rules/<slug>.grep, probes/rules/fixtures/<slug>/bad.<ext>, probes/rules/fixtures/<slug>/good.<ext> and one appended row of probes/registry.tsv. Project vault: indications/<slug>.md and one row of indications/_index.md. It edits no source file, no other registry row and no VAULT.md, and it never commits. A repo without probes/registry.tsv gets one holding a comment header and the new row. The slug matches ^[a-z0-9][a-z0-9-]{0,39}$ and differs from every framework registry id. The stack is one of any harness sql php laravel nuxt flutter python node. The extension matches ^[a-z0-9]{1,8}$ and is the same for both fixtures. install refuses a target that is not a git repository, that is the framework checkout, or whose registry or any path component is a symlink. It writes each file through mktemp and mv -T, and re-runs the accept gate on the bytes it writesa fixed write set is what an operator can approve in one look. Comment text reaches the rules digest only through the indication, and the indication does not exist before approval. The slug lands in a registry cell that the kit runs with bash -c, so it is validated as data. A rename replaces a symlink and never follows it
VR-2 A rule file is data: probes/rules/<slug>.grep holds the keys glob, pattern, severity and message, and the framework's probes/rule-grep.sh runs it with LC_ALL=C grep -E, once over the file list under one timeout of PROBE_RULE_TIMEOUT. The runner refuses any other key, a leading / in a glob, and a message that is not printable ASCII of at most 200 characters. bin/rule-check.sh builds the row from a template, and the model never types a row. Posture: own runs the row with PROBE_PANEL_REPO_CODE=yes, pr never runs it on the host, /v-cr --sandbox runs it in the container (S10). A row written by hand declares yes whenever its run is not the template, and names its install command. verify calls the kit only for a row equal to the template, reports any other row hand-written, prints mislabelled for one that says no, and edits neithera comment is untrusted, so the model may draft a pattern and nothing else. A script could run anything, and one bounded grep cannot. The kit counts repo rows as yes whatever the cell says, so yes keeps list and the docs true and no would be a mislabel. A hand-written row is code, so verify never executes it
VR-3 accept counts findings with probes/rule-grep.sh --check <slug> --rule <draft rule> --repo <repo> | wc -l, and the files the globs select with probes/rule-grep.sh --count-files. It records <n> of <files> files at <sha7> as probe_count in the indication. It refuses more findings than RULE_MAX_FINDINGS, default half of PROBE_PANEL_ROWS (20), a glob that selects no file and an unclosed regex. Zero findings is acceptedhalf of a critic's 40-row block is the most one rule may take. A rule above it fires everywhere and crowds out every other probe. A rule that guards new code finds nothing today
VR-4 /v-cr --sandbox runs the kit in containers of the S0 envelope. The host builds /framework as a read-only copy of git archive HEAD bin lib probes, never the framework root, so vault/ and .git stay outside. It mounts the throwaway clone read-only at /repo, the base rules at /rules and a tmpfs at /tmp, with network: none, an empty environment and the S0 caps. Run 1 runs framework rows. Run 2 runs each template row of the merge base with --only <id>. Hand-written repo rows do not run in the sandbox; the status names them skipped. The host resolves the merge base to a sha, removes probes/ from the clone, and writes the base's registry and *.grep files with git cat-file blob into /rules. A base without probes/ skips run 2 and prints Probes: no base rules. The image comes from VCR_SANDBOX_MAP (user or global), never from an indication. The host passes changed files with --changed-list, so no git runs in the container, and each container has a host wall-clock timeout and the S7 label-based removal. Rows leave through stdout and stderr, cut at PROBE_OUT_MAX bytes. The host passes each stream through the six-field check of probe_check_rows, drops rows whose id is not a row of that run, scrubs with cr_redact_runtime, and writes framework.tsv, framework.status, rules.tsv and rules.status (C-8). A row without a ran: line reads INCOMPLETEeverything a container prints can be forged by the code it ran, so only two byte streams leave it and the host re-checks each row. An allowlist copy keeps vault files out of reach. The base copy blocks a pull request from editing the rules that judge it, and cat-file skips attribute filters. A hand-written row runs pull-request code, so it never shares a container with a template row
VR-5 bin/probe-panel.sh run --posture sandbox --rows-from <dir> tags each row on the host from the run that produced it, never from the container's output. framework.tsv rows are [confirmed], because the container sets PROBE_TOOLS_FROM=image, which stops the kit adding the repo's tool directories to PATH. rules.tsv rows are [confirmed], because run 2 executes only template rows. A container failure prints INCOMPLETE and never runs a yes probe on the host. S10 adds the variable, the posture, --rows-from, --changed-list, --rules-dir, the envelope key and an ADR-009 addendum; none exists todaythe finding row has no origin, so the run supplies it. A template row of the base is a framework-run pattern check that the pull request cannot edit, so it is as reliable as a merged framework probe. ADR-009 stands: no repo code runs outside the envelope, and no output counts as an instruction
VR-6 verify reads an indication's probe: key and prints one line. An id absent from the repo registry prints framework <id> when the framework registry holds it, else orphan <slug> <id> and exit 1. A row that is not the template prints mislabelled <id> with exit 1 when it says no, else hand-written <id>. A template row prints broken <slug>: <reason> with exit 1 when its rule file or a fixture check fails, else drift <slug>: <old> -> <new> when the count changed, else ok <slug> <n> of <files> files at <sha>. Every other line exits 0. On an orphan /v-rule recreates nothing silently: it drafts a rule from the indication's ## Rule and ## Examples, runs the accept gate, and offers three choices: write the rule, drop the probe: key, or leave it. /v-rule passes --repo to bin/indication-route-audit.sh, so it never meets unchecked-probeC-5 defines the key and S8 consumes it. An orphan is a rule whose check vanished, and recreating it unasked would turn an indication's text into code
VR-7 /v-rule reads only comments whose numeric user.id equals gh api --hostname <pr host> user --jq .id and whose user.type is User, through bin/rule-check.sh own-comments. The filter drops a body holding <!-- v-cr: and any comment with performed_via_github_app. The skill reads issue comments, review comments and review bodies with --paginate --slurp. It shows the operator each body fenced as data with its updated_at, and the operator confirms that an edited body is theirs. It stores the comment URL and no body text, stamps source: pr-comment, drafts in a mktemp -d directory, writes nothing until the operator approves, drafts at most 3 rules per run and supports GitHub onlyanyone can comment on a public pull request, and a login can be renamed while an id cannot. /v-cr posts markers built from the hostile diff under the operator's account. A maintainer can edit a comment, so the operator approves the body they see. source: pr-comment keeps the indication out of the sandbox recipe (S0)
