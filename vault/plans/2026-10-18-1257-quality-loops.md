# quality-loops — plan

## Task
Split EXECUTE in `/v-work` and `/v-team` into three loops with separate owners. The execution loop writes production code and runs the repo's static checks on the diff before it calls a unit done. The code-review loop critiques design the way a senior developer would and drops anything a static tool already reports. The testing loop writes tests, measures changed-line coverage against an 80% floor and runs mutation testing on the diff, and independent reviewers label every surviving mutant. Quality tools come from a new plugin extension point `check`, so the vault-quality-gates plugin can supply them; a repo without it falls back to its `lint_command` and `test_command`. Keywords: `check` point, `bin/vault-check.sh`, `commands/_shared/testing-loop.md`, `PROBE_BASE`, `quality.md`, `performance.md`, `testing/design`, `team_max_test_rounds`, `team_max_test_writers`.

## Decisions

| decision | reason | record |
|----------|--------|--------|
| D-1 A new plugin extension point `check`. The framework runs `extend/check.sh <stage> <repo> <base>` with stage `static` or `tests`, only for plugins the repo's `plugins:` line names. Exit 0 measured and acceptable, 1 measured and worse, 2 could not measure; any higher exit is clamped to 2 and reported as "could not run". `vault_plugin_check_declared` answers whether any opted-in plugin declares `check`; no exit code carries that answer | the plugin owns the measurements; a crashed plugin must never read as an absent one | ADR-034 |
| D-2 Both stages measure the working tree against `<base>`. The changed paths are `git diff --name-only -z <base>` plus untracked files, and an untracked file counts as wholly changed. The plugin chooses which tests a `tests` run covers. `bin/vault-check.sh` stops a point at `VAULT_CHECK_TIMEOUT` seconds (default 1800) and exits 2. A `tests` point exits 1 for failing tests only; coverage and survivors never change its exit | the agent has staged nothing when it checks; a full-suite run per round costs an hour in recycling-api | ADR-034 |
| D-3 A `check` point prints one tab-separated line per item: `finding <file>:<line> <rule> <message>`, `failed <test-id> <message>`, `coverage <percent\|none> <floor\|->`, `survivor <file>:<line> <mutator>`, `unmeasured <what> <reason>`. Paths are repo-relative. `<floor>` is the plugin's own configured floor, `-` when it has none; `none` means the diff has no coverable lines. A PHP plugin takes survivors from the Infection JSON log's escaped mutants. `bin/vault-check.sh` passes lines through, capped at `VAULT_CHECK_LINES` (200) and `VAULT_CHECK_BYTES` (12000), and states the withheld count | agents read the lines; the exit decides | ADR-034 |
| D-4 `bin/vault-check.sh <static\|tests> --repo <root> --base <ref>` is the only caller. It exits with the highest point exit. It is the single owner of the floor: on a `coverage` line below max(80, floor) it exits 1, and on a floor below 80 it prints `floor-below <floor> 80`. `coverage none` meets the floor. A declared `tests` point that exits 0 and prints neither a `coverage` line nor `unmeasured coverage` makes it exit 2. With no `check` plugin it runs `lint_command` or `test_command` and prints `fallback scope repo`. On `tests` it also prints `unmeasured coverage` and `unmeasured mutation` lines | one entry point and one floor owner | ADR-034 |
| D-5 The fallback maps exit 0→0, 126 and 127→2, any other nonzero→1. A missing or `absent:` key exits 2 with the reason. A value holding `<…>` or `{{…}}` exits 2 with `<key> is a template`. A trailing ` # comment` is removed first. Keys are read by `vault_md_key` in `lib/vault-md.sh`, moved from `bin/probe.sh` `probe_vault_key`. Opt-in is read by `vault_plugin_opted_in` in `lib/plugin-registry.sh`, with the same two-line refusal as `bin/gate.sh` `plugin_keys` | a template run as shell fails as a redirect and would read as failing tests | ADR-034 |
| D-6 `/v-team` EXECUTE has three loops with separate owners. Execution: production code only. Before a unit is done it runs `bin/vault-check.sh static` from `PROBE_BASE`, fixes findings on changed files, records the rest, and stops after 3 tries, when the rest goes to the operator. A unit is done once no output names a changed file, whatever the exit; under `fallback scope repo` an exit 1 from unchanged files does not hold the unit. Code review: design findings only. Testing: tests only. A test that exposes a production bug returns it to the execution loop: at most 1 return per testing round and 3 per run, each followed by one review round counted in neither cap; past the cap the bug goes to the operator | if either side edits the other's work, a failing test gets "fixed" by weakening it | ADR-034 |
| D-7 Reviewers label each survivor `missing-test`, `weak-test` or `equivalent: <reason>`; writers act on the first two. The testing loop stops when coverage meets max(80, floor) and every survivor is killed or labelled `equivalent`, or at `team_max_test_rounds` (default 3), when the open items go to the operator. Every `equivalent` label is printed to the operator verbatim. When coverage and mutation are `unmeasured`, the loop stops after round 1 once `test_command` exits 0 and the per-test gate holds. A `tests` exit 2 stops the loop at once. In both cases the required output prints `coverage unmeasured: <reason>` | an unkillable mutant makes a fixed score block forever; an unmeasured run must never read as a met floor | ADR-034 |
| D-8 The testing loop lives once in `commands/_shared/testing-loop.md`. Writers are grouped by target file, capped by `team_max_test_writers` (default 2, hard max 3); extra groups queue for the next round. `/v-team` seats the testing reviewer group, so a writer never labels its own survivors. The per-test gate (builds, green 3 times, kills a mutant or a characterization check) moves here from `04-execute-loop.md` §5.2 | one definition of the loop, the gate and the floor | ADR-034 |
| D-15 `/v-work` runs no loops and seats no reviewer agents. Before a unit is done it runs `bin/vault-check.sh static` once, fixes findings on changed files, and runs it once more. After implementation `test-writer-fixer` writes tests in one pass, then `bin/vault-check.sh tests` runs once. Coverage below max(80, floor) and every survivor go to the operator as open items, never labelled; `coverage unmeasured: <reason>` is always printed. The floor and the per-test gate are read from `commands/_shared/testing-loop.md` | `/v-work` is the light command for simpler tasks; `/v-team` owns the loops | ADR-034 |
| D-9 `commands/v-team/steps/04-execute-loop.md` is renumbered: §5.1 Implement, §5.2 Code-review loop, §5.3 Testing loop, §5.4 Self-review. Every file and `lib/shared-module-rules.tsv` row citing the old §5.2 or §5.3 is updated; accepted ADRs are not edited | review must see stable code before tests are written against it | local |
| D-10 `commands/_shared/critic-panel.md` gives each critic the `finding` lines of its changed files from `bin/vault-check.sh static`. At synthesis, a finding whose `file:line` and claim match one of those lines is dropped; under fallback the match is exact text in the lint output. A design finding is `confirmed` with one of: an existing symbol `path:line`; a package command and its output; a smaller rewrite applied in a scratch worktree with `bin/vault-check.sh static` and the touched tests passing, command and output in `check`; a measurement with its command and output. Any other rewrite is `advisory` and at most MINOR | design critique cannot cite tool output; an unrun rewrite is a taste preference | ADR-034 |
| D-11 `personas/_shared/quality.md` owns simpler solutions, over-built code, reuse of an existing symbol, and an existing package. Its line-count, nesting, dead-code and duplicate-block items stay only under one condition: no static check ran (fallback with `lint_command: absent:`, or exit 2). `personas/_shared/performance.md` owns the cost of the approach. The id `quality` stays | 17 repos have no linter; renaming the id rewrites every pack overlay for no behaviour change | local |
| D-12 On diff review `personas/_resolution.md` §2 seats architect, `quality` and `correctness` by default. A `performance`, `security` or `skeptic` trigger raises `team_max_parallel_critics` up to its hard max of 5, recorded in the trail. The critic cap is stated only in `_resolution.md` §2; `commands/_shared/critic-panel.md` §(b) and `lib/shared-module-rules.tsv` reference it | the senior-dev panel the operator asked for, with one cap home | ADR-034 |
| D-13 Three new test-design generators in `personas/_shared/testing/design/`: `api-contract-mapper` (status, shape and auth per endpoint; trigger: endpoint or route change), `abuse-case-designer` (another user's data, extra fields, permission bypass, injection; trigger: auth, tenant or user-data change), `performance-budget-designer` (query and time budgets; trigger: hot path or list endpoint). `business-logic-cartographer` and `boundary-property-explorer` sit on every `(f2)`; the others on a trigger; `team_max_test_designers` defaults to 5 | ADR-011 makes generators the authors of the Test backlog; ADR-006's critic-cluster rule does not apply to them | ADR-034 |
| D-14 A full `/v-team` run is restated in `commands/v-team.md` as about 9 to 45 agent spawns: 2 to 5 designers, 3 to 5 review critics over up to 2 rounds, up to 2 writers and 3 testing reviewers over up to 3 rounds, and up to 3 return rounds of up to 5 critics | the operator chooses `/v-team` over `/v-work` from that figure | local |

## Rollback
Revert the three commits. Nothing migrates and no repo's `VAULT.md` changes. A plugin that ships `check.sh` before a revert is ignored afterwards; `bin/vault-plugin.sh add` would then refuse to re-register it until its manifest drops `check`.

## Test design dossier
Exit partitions for the fallback: command exit 0 → 0; 1 to 125 → 1; 126 → 2; 127 → 2. Key partitions: missing → 2; `absent: x` → 2; `absent:` with an empty reason → 2; a value holding `<path>` → 2; a value ending in ` # note` runs without the comment. Plugin partitions: none registered; registered but not opted in; opted in without `check`; opted in with `check` exiting 0, 1, 2, 3 and 127. Floor partitions: coverage 85 floor 80 → 0; coverage 75 floor 70 → 1 and `floor-below`; coverage 85 floor 90 → 1. Property: the exit is the maximum of the clamped point exits. Fault hypothesis: a plugin path with a space breaks the call.
