## Learned
- A foreground Bash call dies at 10 minutes, so every goal run is a background call; the device-sync goal limit is 70 min.
- A gate helper called in `$(...)` loses its refusal count, so the gate exits 0 after printing `REFUSED`. `goal_script` and `goal_master` hit this; both now set globals or re-raise exit 2.
- A second `flock` on the same file in one process blocks on itself, so helpers never lock and each writing command locks once.
- A lock fd inherited by a process the goal script leaves running keeps the run lock forever; the child closes fds 8 and 9.
- `pm-plan.sh order` refused this plan's own S2 pickup (`no repo column`); S2 was claimed by hand and S2 fixed `order`.
- Hand-run mutation testing found 8 survivors after the first test draft; the strengthened suite kills each one re-run.

## Behaviors & rules
- An opted-in plan whose `goal script` row is empty → `gate.sh goal` refuses.
- `goal baseline` while `baseline` is empty: script exits 0 → refused; exits 1 → `<date> exit 1` written; exits 2 or not written yet → note, nothing written.
- `goal close <plan> <S> <ids>` with an id another session owns → refused and nothing written; edge: a `pass` written by another session's uncommitted `goal close` is exempt through the machine-local ledger.
- `goal last` with any row not `done` or `dropped` → `waits`, no run; edge: a held run lock → `already running`, nothing written.
- A case group passes only when no log line holding its case text fails and at least `count` such lines pass.
- `pm-plan.sh gap` at `gap_rounds: 3`, with an unknown id, an `operator` case or an unowned case → refused and the plan is unchanged.
- A CRLF master → every goal writer, `set` and `gap` refuse by name.
