# the /v-rule skill and the sandbox probe split (S8)

## Goal
Build the on-demand `/v-rule` skill (session S8 of `vault/plans/2026-09-21-0900-architecture-first-planning.md`). It turns the operator's own review comments into an indication, a rule file, two fixtures and one registry row. Also design how `/v-cr --sandbox` runs repo-code probes.

## Did
- Planned it as `vault/plans/2026-09-21-1430-v-rule.md` (eight decisions, eight criteria, graders written first). Three critics changed the sandbox design and the graders before any code existed.
- Built `probes/rule-grep.sh` (declarative `.grep` rules), `bin/rule-check.sh` (`row`, `accept`, `install`, `verify`, `own-comments`), `commands/v-rule.md`, and the Rule files section of `commands/_shared/probe-kit.md`.
- Split the sandbox probe build into session S10. The design stays in the plan as VR-4 and VR-5; the master plan gained the S10 row and contract C-8.
- Two implementation reviews found 4 majors: relative `--repo`, a registry with no trailing newline, control bytes forging a finding row, and symlinks in the draft. All are fixed with tests.
- `bin/gate.sh verdict --run` reports SC-1 to SC-8 MET; the full unit suite fails only the 5 tests that fail on `HEAD`.

## Learned
- The probe kit lost its temp directory in about 5% of runs: killing the watchdog with TERM ran an inherited exit trap. `kill -KILL` in `lib/probe-run.sh` fixes it.
- Command substitution drops NUL bytes, so a `grep -Z` stream needs the NUL turned into another byte before it is stored.
- `bin/gate.sh all` has no `--run` option; only `verdict` runs the graders.
- A registry row typed by the model is arbitrary shell, because the kit runs a repo `run` cell with `bash -c`. The row is generated from a template instead.

## Behaviors & rules
- A rule is accepted only with a firing bad fixture, a silent good fixture, a glob that selects a file and at most 20 findings on the current repo.
- `install` writes the rule, two fixtures and one template row, refuses a symlinked path, the framework checkout and a repeated id, and writes nothing on refusal.
- `verify` on an id absent from the repo registry → `framework <id>` when the framework holds it, else `orphan <slug> <id>` with exit 1.
- `own-comments` keeps only comments whose numeric user id equals the operator's, type `User`, with no `/v-cr` marker and no app author.
