# probe-kit-core-s4

## Goal
Build session S4 of the architecture-first master plan: the probe kit core, with its tool claims verified before any registry row named a tool.

## Did
- Checked the 12 tool claims in the master plan. Seven were wrong or partly wrong. The record is `vault/research/probe-tool-verification.md`.
- Planned S4 with three reviewers over two rounds and wrote its graders first. The plan is `vault/plans/2026-09-21-1130-probe-kit-core.md`.
- Built `bin/probe.sh` with `list`, `detect`, `run`, `diff` and `scale`, the libraries under `lib/probe-*.sh`, and three native probe scripts: `probes/harness.sh`, `probes/sql-schema.sh` and `probes/similar-symbols.sh`. Rows for lizard, typos and `claude plugin validate` use parsers tested on captured output.
- Reviewed the diff in two rounds. Two blockers, both in git handling, and several majors were fixed. Commits `1af574a` and `e9060ab`.
- Tests: `tests/unit/probe.bats` 40 cases in the BusyBox container; the suite has 872 tests and the same 5 fail as on `HEAD`.

## Learned
- Running git in an untrusted repo runs its code. Four routes reproduced: `core.fsmonitor`, a `filter.<name>.clean` command, lazy fetch through `remote.origin.uploadpack`, and hooks. A `-c key=value` override splits at the first `=`, so a filter named `a=b` escaped the first fix. Overrides travel in `GIT_CONFIG_KEY_n` variables.
- An environment variable cannot hold a NUL byte, so a NUL-separated file list is passed as the path of a list file.
- `timeout` does not stop a process group on BusyBox and does not cap output. A `set -m` job with a watchdog and `ulimit -f` does both.
- A grader that passes on the first run proves little. Nine seeded bugs showed which graders could fail, and two graders could not catch a broken stop-word rule until a test was made to.
- `awk` reads a file operand named `a=b.md` as a variable assignment. Feed files by redirection.
- A tracked path can lead through a symlinked directory. Checking only the last path component leaks the target.
- BusyBox `awk` is quadratic on one long line unless the line is split into an array first.

## Behaviors & rules
- Repo has its own `probes/registry.tsv`, caller passes no `--allow-repo-registry` → its rows never run.
- Registry row names a tool that is not installed → `absent: <id>: <install command>` on stderr, exit 2, and the install command never runs.
- Probe prints a row with the wrong field count, severity or line → that probe fails, prints no row, and the run exits 2.
- `diff` in a repo whose config defines a filter, fsmonitor or hook command → none of them runs; outside git it exits 2.
- Tracked path with a symlink in its directory, or a file name with a tab or newline → the probes skip it.
- `--only` names no row at the stage → exit 2.
- Tool row exits nonzero and prints nothing → failed, never reported clean.
