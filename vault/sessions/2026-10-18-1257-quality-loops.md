# quality-loops

## Goal
Make `/v-team` and `/v-work` run static analysis while code is written, enforce 80% changed-line coverage with mutation testing on the diff, and give the code-review panel a senior-developer mandate.

## Did
- Added the plugin extension point `check` and `bin/vault-check.sh <static|tests> --repo --base` (commit `09f56bd`). An opted-in plugin's `extend/check.sh` measures the stage; with none, the repo's `lint_command` or `test_command` runs and the output says `fallback`.
- Moved the `VAULT.md` key reader from `bin/probe.sh` into `lib/vault-md.sh` `vault_md_key`.
- Split `/v-team` EXECUTE into §5.1 Implement, §5.2 Code-review loop and §5.3 Testing loop; the testing loop lives once in `commands/_shared/testing-loop.md` (commit `1775554`). `/v-work` runs one static check and one test pass, no loops.
- Rewrote `personas/_shared/quality.md` (simpler, reused, not over-built) and `personas/_shared/performance.md` (cost of the approach); diff review seats architect, `quality` and `correctness` by default; `commands/_shared/critic-panel.md` gives critics the static output and drops restated tool findings (commit `6af5f9b`).
- Added test designers `api-contract-mapper`, `abuse-case-designer`, `performance-budget-designer`, seated by trigger.
- Fixed the bugs the code review confirmed (commit `003b53c`); every success criterion of `vault/plans/2026-10-18-1257-quality-loops.md` is MET via `bin/gate.sh verdict --run`.

## Learned
- vault-quality-gates already measured static analysis, diff coverage and Infection; the gap was an extension point, not a tool. New required `VAULT.md` keys would have refused ~90 onboarded repos at session start.
- `guard.sh commit` measures the index only, so a static check called before staging sees no edits; the plugin needs a working-tree target relative to `<base>`.
- Several repos write `test_command` as a template (`phpunit <path> [--filter=...]`); run as shell, `<path` is a redirect that fails and reads as failing tests.
- `vault_plugin_list` returns 1 on a duplicate registry row; a caller that reads that as "not registered" turns a plugin's exit 1 into a silent fallback.
- The unit suite fails 13 tests on `c0fb5f6` before this work; `checks/quality-loops-SC-6.sh` lists them by name.

## Behaviors & rules
- an opted-in `check` point exits above 2 → `bin/vault-check.sh` exits 2 and does not run the fallback
- `tests` output has `coverage <pct> <floor>` with pct < max(80, floor) → exit 1; edge: floor < 80 prints `floor-below <floor> 80`; `coverage none` meets the floor
- a `tests` point exits 0 and prints neither `coverage` nor `unmeasured coverage` → exit 2; edge: exit 1 with no coverage line stays 1
- a fallback key that is missing, `absent:`, a `<placeholder>` template or invalid shell → exit 2 with the reason; a plain redirect `< in > out` runs
- a base ref that is not a commit, or a registry that cannot be read → exit 2
- a registered `check` plugin the repo's `plugins:` line does not name → never runs
