# S10 sandbox probe stage for /v-cr --sandbox

## Goal
Run the executes-repo-code probes and the base repo's rule files inside the `/v-cr --sandbox` container, and tag their rows for the review panel.

## Did
- Wrote seven graders and two fixtures (a docker test double, a fixture repo builder) before any product code: `checks/sandbox-probe-SC-1.sh` to `-7.sh`.
- Planned in `vault/plans/2026-09-21-1600-sandbox-probe.md`, with 12 decisions (SP-1 to SP-12); four reviewers revised it once, and two reviewers revised the code once.
- Built the host driver `bin/probe-sandbox.sh`, `probe.sh --changed-list`, `PROBE_TOOLS_FROM=image`, posture `sandbox` with `--rows-from`, and `cr_probe_image`.
- Wrote section S8 of `commands/v-cr/sandbox.md`, steps 2.6 and 3.1 of `/v-cr`, the probe-kit lines, one panel sentence and an ADR-009 addendum.
- `bin/gate.sh verdict <plan> --run` reports SC-1 to SC-7 MET; the full unit suite fails only the 5 known tests. Commit `a6f2660`.

## Learned
- `ulimit -f` limits files and not pipes, so the host writes docker's streams to files under the limit and compares the size.
- The bats test image has an entrypoint (`bats`), so the driver starts every container with `--entrypoint bash`.
- Docker cannot create a mount point inside a read-only mount, and uid 65534 cannot read a 0700 `mktemp` directory: the driver pre-creates `probes/` and sets `a+rX`.
- `tr '\000-\037'` on a status stream turned newlines into spaces and merged every status line into one; only a real-shape test found it.
- Alpine `tar` lacks `--no-same-owner`; `cp --parents --no-preserve=all -t` from a NUL list is portable and stays inside the copy.
- `bin/gate.sh criteria` refuses a check name that two plans claim, so an earlier plan's row had to change.

## Behaviors & rules
- Base row is hand-written → it never runs in the sandbox; the status reads `skipped: <id>: hand-written row does not run in the sandbox`.
- Container prints a row for an id that did not run → the host drops the row and writes `failed: <run>: rows named an id that is not a row of this run: <n>`.
- Image, docker or the `probe-image` key is missing → the driver exits 3 and no repo-code probe runs on the host; step 3.1 runs posture `pr`.
- Base has no `probes/registry.tsv` → `no-rules:` and the run reads complete.
- Posture `sandbox` → every row is `[confirmed]`, none is demoted, and `bin/probe.sh` is never called.
